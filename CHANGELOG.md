# Changelog

## Unreleased
- Files under `.claude/`, `.codex/`, `.gemini/` or `.cursor/` `docs/` and `reference/` count as instruction files (#1).
- OpenCode/Kilo: `skill` results are checked as instruction files, not as untrusted content (#2).
- `Task`/`Agent` results are scanned for injection; out-of-range thresholds fall back to their defaults (#3).
- OpenCode 2 is now an ask-only gate: `execute.before` only records the call, and `permission.hook("evaluate")` sends it to Jev solely when OpenCode's own rules resolved to `ask`. A rule's `allow` runs untouched and a `deny` is final, so an allowed call costs no Jev request and uploads nothing. Jev's answer then replaces the prompt (`allow`), blocks it (`deny`, with its message as the reason), or, when Jev wants a human, raises the guard's own prompt for that one call (OpenCode's dialog shows only the operation, not `e.message`), so `./tui` can render the scores and the diff; a refusal there turns the call into a deny. An assessment failure keeps the human prompt — never an automatic allow. Result scanning becomes opt-in (`JEV_GUARD_SCAN_RESULTS=1`) so the gate does not send tool output either. Practical consequence: shell commands are only protected if the rules leave them as `ask`.
- Every `JEV_GUARD_*` setting now falls back to `~/.jev-guard/config.json` (same name, environment wins), so a host started by an IDE daemon or a service manager — with no login shell to export anything — still gets the configured policy and not the defaults.
- OpenCode 2 honours `JEV_GUARD_FAIL_CLOSED`: an unassessable `ask` is denied instead of falling back to the plain prompt, and that flag wins over the new `JEV_GUARD_ESCALATE_CLOSED=1`, which instead raises the guard's own prompt with "the assessment API was not available… this call was not judged" and no score bullets.
- The OpenCode 2 banner reads as a request instead of a score dump: the heading names the kind of call ("a shell command needs your approval", "an edit needs your approval"), a `What:` line names the tool and the exact command or path, and every score carries a word for what it means at the policy boundary it belongs to — `• risk: MODERATE — 2.0 (0–3)`, `• approval: SUGGESTED — 0.71 (0–1)`, `• you asked for it: PROBABLY — 0.59 (0–1)`, `• untrusted source: CLEAN — 0.07 (0–1)`, `• confidence: HIGH — 0.98 (0–1)` (MINIMAL/LOW/MODERATE/SEVERE/CRITICAL, UNLIKELY/MAYBE/LIKELY/SUGGESTED, NO/UNCLEAR/PROBABLY/YES, CLEAN/UNLIKELY/SUSPICIOUS/PLANTED, LOW/MEDIUM/HIGH).
- The OpenCode 2 banner queues asks per session instead of overwriting: a second pending request no longer erases the first assessment, a reply removes the request it names (or the oldest when it names none), and the banner says how many more are waiting. The operation shown is the host's own permission resource rather than a 160-character preview, and longer commands are cut at 240.
- The OpenCode 2 banner also draws what an edit changes: `metadata.diff` carries a trimmed `- old` / `+ new` view (`previewDiff` in `src/guard.js`: common leading and trailing lines stripped, 12 lines and 700 chars at most, long lines cut, a count for the rest), rendered between the heading and the scores, green for added and red for removed. `write` shows its content as additions; a shell call has nothing to diff.
- OpenCode 2's `question` tool — the one that asks the user — is read-only for the guard, like `ask_question` already was for other hosts; a prompt to the human is never assessed, denied or turned into a prompt about a prompt. The MCP resource readers (`read_mcp_resource`, `list_mcp_resources`) join them.
- `JEV_GUARD_WORKSPACE_WRITES=1`: file edits inside the project directory no longer cost a Jev call, for hosts that hand the adapter a `cwd` (all of them do). Only the write tools qualify — `edit`, `write`, `multiedit`, `notebookedit`, `create_file`, `write_file`, `replace_file_content`, `delete` — and only when the target resolves inside `cwd`; `.git`, `secrets/`, `.env*` and key files keep being assessed, patch tools are excluded because their input names no single target, and shell tools are never included because a command can leave the workspace whatever its text says. Off by default, so every existing install keeps the old behaviour.
- `JEV_BASE_URL` accepts plain `http` on RFC 1918 private addresses (10/8, 172.16/12, 192.168/16) and all of 127/8, e.g. a Kev in Docker at 172.17.0.1 (#6).
- OpenCode 2: the reasoning behind each ask reaches the user from the plugin's new `./tui` entry (`src/tui.js`) — the permission dialog renders only the action name and a server plugin has no UI channel, so the ask carries the assessment in `metadata`. It is rendered in the `session.composer.top` slot of the asking session: a heading, one bullet per Jev score with its scale in brackets (`• risk 1.9 (0–3)`, `• approval 0.37 (0–1)`, `• you asked for it …`, `• untrusted source …`, `• confidence …`), the exact call on its own `$` line, and a hint; tabs without a pending ask show nothing, and any answer from any client clears it. The asking itself stays OpenCode's normal permission prompt. (A toast was tried first and rejected: it is broadcast to every open TUI, expires on a timer, and `ui.toast` cannot be dismissed. A `session.panel` was tried next and rejected too: `ui.panel.open` targets the session current at that moment and a plugin has one active panel, so an ask from another tab surfaced in the wrong one and disappeared on a tab switch.)

## 0.3.1 — 2026-09-18
- Jev calls retry on 429/5xx *and* network errors inside one time budget (`JEV_GUARD_TIMEOUT_MS`, 20 s), so a hook never outlives its host's ~30 s timeout and fail-closed actually fails closed.
- Instruction-file scans share one content-hash cache across the session-start sweep, `InstructionsLoaded`, `Read`/`Skill` results and `scan-skills`; cache hits carry only Jev's answer and the verdict is rebuilt.
- An answer with no `kind` is treated as serious instead of crashing the message builder; `JEV_GUARD_SKILL_P` / `JEV_GUARD_SKILL_SERIOUS_P` documented.

## 0.3.0 — 2026-09-18
- Context: every decision now sees the user's recent prompts, the agent's stated intent, recent decisions and flagged content (`src/context.js`, `src/session.js`). Two new questions: `user_requested` (turns ask into allow when the user asked for exactly that) and `from_untrusted` (denies a call that carries out an instruction planted in something the agent read). Prompt hooks on every host feed the memory; pi, OpenCode and ACP read the session directly.
- Instruction files: skills, plugins, rules and `CLAUDE.md`/`AGENTS.md` are checked with their own questions (`INSTRUCTION_QUESTIONS`) at session start, on `InstructionsLoaded`, when a `Skill` runs, when the agent reads one, and via `jev-guard scan-skills`; results cached by content hash.
- Third-party skill/plugin/MCP installs count as level-2 (ask) actions. Instruction-file thresholds: `JEV_GUARD_SKILL_P` (0.8, unrelated side effects) and `JEV_GUARD_SKILL_SERIOUS_P` (0.45, the serious kinds); answers cached by content hash and shared by the sweep and the read/Skill hooks.
- OpenCode: expose `main` and `exports["./server"]`, which is what OpenCode's npm plugin loader resolves; `"plugin": ["jev-guard"]` now works from the registry.
- `check` / `scan` exit 3 with a one-line error instead of a stack trace when Jev is unreachable.

## 0.2.0 — 2026-09-17
- Adapters for Copilot CLI, Gemini CLI, Cursor and OpenCode; the hook script recognises each host's payload.
- Marketplace manifests: Claude Code (`.claude-plugin`), Codex (`.agents/plugins`), Copilot (Claude layout), Gemini (`gemini-extension.json`, asks for the key on install), Cursor (`.cursor-plugin`).
- `jev-guard key` stores the API key in `~/.jev-guard/config.json` for hosts that don't inherit a shell.
- `install` writes the absolute `node` path and refuses to run from the npx cache.
- Icon, works-with strip and launch video.
